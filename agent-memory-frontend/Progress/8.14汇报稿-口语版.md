## 一、先说这个前端整体长什么样

咱们这个前端，是一个"记忆管理中台"，覆盖从"智能体接入 → 记忆写入 → 多层管理 → 生成融合 → 检索 → 上下文返回 → 运行监控"的完整链路。侧边栏一共 7 大分区、30 来个页面，我按分区给大家过一遍：

**第 1 区：智能体接入与记忆数据写入**
- 智能体注册接入：注册智能体拿身份凭据；接入已有智能体，选平台（Dify / Open WebUI / 阿里云 IMS / 智谱）就自动切字段
- 场景标识配置：建业务场景，把智能体、任务、记忆隔离开
- 接口密钥配置：维护 Agent ID 和 API Key，支持轮换
- 记忆数据导入：JSON/CSV 导入对话、会话摘要、任务过程，强制关联 Agent ID
- 数据校验与标准化：导入前校验文件结构，预览标准化结果

**第 2 区：多层记忆管理**
- 用户级记忆：管用户偏好、稳定事实、长期约束
- 会话级记忆：按会话看历史摘要和上下文
- 任务级记忆：按任务管目标、进展和结果
- 智能体级记忆：智能体名下全部记忆

**第 3 区：记忆生成与去重融合**（10 个预设）
- 3 个分析类：用户偏好提取、关键事实提取、关键实体人物生成——"选记忆 → 执行分析 → 差异化结果"
- 7 个文本类：任务状态生成、历史决策沉淀、冲突检测、冲突记忆去重、相似记忆去重、记忆融合管理、低价值内容过滤——每个结果形态都不一样

**第 4 区：多信号融合记忆检索**（5 种子模式 + 综合）
- 语义向量检索、关键词检索、元数据过滤、融合排序、Top-K 返回

**第 5 区：记忆上下文返回**（4 种形式 + 综合）
- 结构化 JSON、文本上下文片段、相关性筛选、长度控制与压缩

**第 6 区：接口与监控**
- 接口健康检查、调用状态监控、联调记录

**第 7 区：系统设置**
- 基础连接设置（后端地址）、本地用户身份（联调用 User ID）

另外还有几个不在菜单里的：**首页系统总览**（实时监控看板 + 数据总览）、**任务过程管理**，以及整套**登录体系**（登录/注册/密码找回/个人中心，带登录守卫）。

## 二、8.13 那批，六项改造，全落地（重点）

### 1. 多层记忆管理页，彻底整改

这个是工作量最大的一件。主要改了这几处：

- **功能边界拆干净了**：原来记忆管理页里混着"偏好分析"这种分析类功能，现在全部迁走，记忆页就管查询、浏览、增删改查。
- **交互重做**：原来要手动输 Session ID / Task ID 这种输入框，作废了。现在就是点"用户级 / 会话级 / 任务级"标签切换，列表自动刷新。
- **勾选能力**：列表可以单选、多选，还能跨会话跨任务勾选组合，供后面分析用。
- **搜索升级**：顶部关键词搜索 + 高级查询（时间范围、标签、会话、任务都能筛）。
- **加了统计卡**：每个层级顶部有对应的统计，比如用户级就是总记忆数、活跃用户、今日新增。
- **操作列统一**：每行固定"查看 / 修改 / 删除 / 更新"四个按钮，三个层级交互完全一致，就是字段不一样。

### 2. 分析功能迁到生成页

偏好提取、关键事实提取、关键实体人物生成这三个分析功能，统一挪到了「3. 记忆生成与去重融合」页，走的是"**选记忆 → 执行分析 → 展示结果**"这条标准流程。

我们还抽了一个通用组件叫 `MemorySelector`（就是层级切换 + 列表勾选），记忆页和生成页共用，一处开发两处复用，也不用跨页共享状态。分析结果是**动态字段**——偏好维度不写死，模型出啥就渲染啥；后端没有专项接口，先用演示数据兜底，接口好了无缝切换。

### 3. 智能体接入增强

按梁闯给的《智能体接入接口.pdf》：接入表单加了**平台来源选择**，Dify、Open WebUI、阿里云 IMS、智谱四个平台，选哪个就自动切哪个平台的字段。另外加了**采集频次配置**——手动采集 / 定时采集（每小时、每天、自定义间隔）。

### 4. 首页看板，加数据追溯

在原来的频次 + 成功率基础上，补了三块：**后端健康状态**（接口正常不正常、数据库连没连上）、**请求路径统计**（每个接口被调了多少次）、**失败调用追溯**（失败了能下钻看到 Trace ID、错误码、耗时）。

### 5. 检索结果展示完善

原来检索完结果区比较简陋。现在提交检索后一定有结构化的结果列表，空的时候用演示数据兜底并标注，还加了相关度进度条、内容提示和失败引导。

### 6. 登录页（放在最后，已完成）

复用了开源知识图谱项目的登录结构，适配成 React 组件。做了**登录守卫**（没登录直接访问内部页会跳回登录页）、**mock 认证**（admin/admin123 这种）、GitHub 登录占位入口、三步密码找回、个人中心。

## 三、8.13 追加：界面差异化，解决"都长一个样"

老师提的这个点，我们理解是：统一前置流程（选记忆、勾选、触发分析）是规范，要保留；需要差异化的是**结果展示区**。现在是这样：

**生成模块**，每个预设结果形态都不一样：
- 用户偏好提取 → 画像标签墙 + 雷达图 + 维度明细表
- 关键事实提取 → 事实条目列表 + 关联树
- 关键实体人物生成 → 实体人物卡片网格
- 任务状态生成 → 任务进展时间线
- 历史决策沉淀 → 决策卡片
- 冲突检测 → 新旧记忆左右对比 + 冲突高亮
- 冲突记忆去重 → 冲突清单 + 解决状态
- 相似记忆去重 → 相似分组卡片
- 记忆融合管理 → 融合前后对照
- 低价值内容过滤 → 灰色丢弃清单 + 原因标签

**检索模块**，6 个模式也各不一样：语义是相关度排序列表、关键词是命中高亮、元数据是左侧筛选面板、融合是信号权重条、Top-K 是截断条、全部是综合仪表盘。

**上下文模块**，5 个模式：JSON 是结构树、文本是可注入卡片、相关性是分级列表、长度是 Token 预算条、全部是综合视图。

合计大概 18 种结果形态，全部基于现有返回结构做纯前端渲染差异化，没动后端。

## 六、接口对接的现状

我们对了一遍后端接口文档和前端实际调用：

- 文档里 44 个唯一接口，**前端实际用上了 21 个**，另外 `/health` 是前端在用但文档没收录的。

## 八、遗留事项和下一步

### 等后端就绪的（都不是前端问题，前端都兜底了）

1. **LLM/Embedding 的 Key 是空的** → 记忆写入、向量检索走降级模式。
2. **后端没有分析类专项接口** → 偏好/事实/实体先用前端演示引擎。
3. **后端认证没开**（`AUTH_ENABLED=false`）→ 登录是 mock 认证，OAuth 是占位。
4. **后端没有采集任务接口** → 采集配置先存 localStorage。
5. **`embedding_client.py` 缺一行 `import json`**（bug 已定位）→ 导致检索降级、上下文接口直接失败。这个本地联调补一行就能好，正式环境需要后端改。
6. **`/memory/context` 没有降级兜底** → 上下文 5 个模式界面完好，但拿不到数据。
7. pgvector、Kafka、Redis 没配置 → 非致命，单机演示没影响。

- 会话/任务级列表个别字段（比如"会话主题摘要"）等后端补字段，前端先聚合兜底。
