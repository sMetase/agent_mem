## 一、画像可视化字段（P1）

### 1.1 `POST /api/v1/memory/profile` 【扩展返回】

前端当前使用：`{persona, scene_id, changed_scenes}`。

**请新增 `visual` 与 `stats` 字段**（前端按此渲染雷达图 / 类型分布 / 趋势 / 标签，缺省时前端用演示数据兜底并标注）：

```json
// ← 期望返回（新增字段）
{
  "code": 0,
  "data": {
    "persona": "用户画像自由文本…",
    "scene_id": "scene_xxx",
    "changed_scenes": 2,
    "stats": {
      "total_memories": 42,
      "active_memories": 38
    },
    "visual": {
      "radar": [
        { "dimension": "专业能力", "score": 82 },
        { "dimension": "沟通协作", "score": 70 },
        { "dimension": "决策效率", "score": 65 },
        { "dimension": "创新探索", "score": 55 },
        { "dimension": "风险意识", "score": 74 }
      ],
      "memoryTypeDist": [
        { "type": "fact", "count": 18 },
        { "type": "preference", "count": 10 },
        { "type": "task_state", "count": 6 },
        { "type": "process", "count": 5 },
        { "type": "correction", "count": 3 }
      ],
      "tags": ["BOM转换", "供应商", "交期管理", "质量追溯"],
      "trend": [
        { "date": "2026-08-01", "count": 5 },
        { "date": "2026-08-08", "count": 9 }
      ]
    }
  }
}
```

**字段说明**：
| 字段 | 类型 | 说明 |
|---|---|---|
| `stats.total_memories` | int | 画像相关记忆总数 |
| `stats.active_memories` | int | 有效记忆数 |
| `visual.radar` | array | 画像维度评分（dimension 中文标签，score 0-100），维度数量/命名由后端定，前端按返回渲染 |
| `visual.memoryTypeDist` | array | 5 类记忆分布（`type` 为 5 类枚举 `fact/preference/task_state/process/correction`） |
| `visual.tags` | array | 高频关键词/标签 |
| `visual.trend` | array | 记忆随时间的数量分布（date 为 ISO 日期） |

> 口径：若一时无法生成雷达维度/趋势，可先返回 `memoryTypeDist` 与 `tags`（有记忆即可统计），前端缺省字段继续演示兜底。

## 二、外部接入源管理与采集（P2）

### 2.1 场景
前端「远程 API 导入」需要管理多条外部数据源（Open-Web-UI / 外部智能体），支持启停与（定时）拉取对话记录。**纯前端无法可靠定时，且直连外部 API 受 CORS 限制**，需后端提供接口并由后端 worker 执行采集。

### 2.2 建议接口（路径可调整）

**CRUD**：`/api/v1/integration-sources`
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/integration-sources` | 新增接入源 |
| GET | `/integration-sources` | 列表（分页，可选按 is_active 过滤） |
| GET | `/integration-sources/{id}` | 详情 |
| PUT | `/integration-sources/{id}` | 更新（含 is_active 启停） |
| DELETE | `/integration-sources/{id}` | 删除 |

**拉取**：
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/integration-sources/{id}/pull` | 手动触发拉取（前端「立即拉取并导入」用） |
| GET | `/integration-sources/{id}/status` | 最近拉取时间 / 上次结果 / 拉取到的会话数 |

**接入源对象（前端期望字段）**：
```json
{
  "source_id": "src_xxx",
  "name": "Open-Web-UI 生产环境",
  "source_type": "openwebui",          // openwebui | external_agent
  "base_url": "http://10.0.0.5:8080",
  "api_key": "…",                      // 写入时明文，列表仅前缀/掩码
  "is_active": true,
  "last_pull_at": "2026-08-24T10:00:00Z",
  "last_result": "success",            // success | failed
  "last_pull_count": 120,              // 上次拉取会话数
  "created_at": "…"
}
```

**采集行为约定**：
- 后端 worker 定时轮询 `is_active=true` 的接入源，拉取对话后走现有 `/memory/write`（`interaction_type=session`）链路落库。
- 拉取格式兼容 Open-Web-UI 导出（顶层数组、`history.messages` 对象 + `parentId` 树）——前端清洗器已支持该格式；后端如自行解析需对齐同一契约。

## 三、大模型服务配置（P2）

### 3.1 场景
当前大模型接口（DeepSeek 等）写死在后端本地。前端新增「大模型服务配置」界面，支持多条配置 + 独立启停，**需要后端提供配置存取并让服务端 worker 读取生效**（替换写死的单模型）。

### 3.2 建议接口（路径可调整）

`/api/v1/llm-configs`（CRUD，含 `is_active` 启停）：
| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/llm-configs` | 新增配置 |
| GET | `/llm-configs` | 列表 |
| PUT | `/llm-configs/{id}` | 更新 / 启停 |
| DELETE | `/llm-configs/{id}` | 删除 |

**配置对象（前端期望字段）**：
```json
{
  "config_id": "cfg_xxx",
  "name": "DeepSeek 主模型",
  "provider": "deepseek",             // deepseek | openai_compatible | custom
  "base_url": "https://api.deepseek.com",
  "api_key": "sk-…",                  // 写入时明文，列表掩码
  "model": "deepseek-chat",           // 可选
  "is_active": true,
  "created_at": "…"
}
```

**生效约定**：`is_active=true` 的配置作为可用模型池，供后端调用链路由选择；多条可同时启用。
