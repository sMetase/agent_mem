## 二、会议对前端的核心改造意见

### 2.1 界面布局重构

1. **功能区块分离**：将原有单一输入框拆分为「选择区」+「结果展示区」，两者并列排布。
2. **菜单项精简**：去除冗余的「通用记忆建模」菜单，保留「多层记忆管理」作为核心入口。

### 2.2 配置与监控增强

3. **注册与接入拆分**：在「智能体接入」部分，将「注册」与「接入」拆分为两个独立操作。
4. **实时监控看板**：首页增加图表，支持按小时、天、周维度查看接口调用实时频次与成功率。

### 2.3 用户偏好分析修正

5. **输入对象调整**：纠正仅针对单次输入的局限，改为基于**用户级 / 会话级 / 任务级历史记忆集合**进行分析。
6. **展示形式升级**：前端不再仅显示原始文本，需增加**雷达图、表格**等形式，直观展示用户关于**颜色、型号、工艺**等维度的偏好特征。

### 2.4 数据采集策略

7. **强制关联智能体 ID**：非标准来源数据支持 JSON 文件导入，但需**强制关联智能体 ID** 以确保数据对齐。

### 7.5 剩余基础设施问题（需配置后完整启用智能链路）

**① mem0 智能链路未配置（Key 为空）**
- 后端 `.env` 中 `DEEPSEEK_API_KEY`、`SILICONFLOW_API_KEY` 为空。
- 影响：记忆写入/检索走**降级模式**（`mode: degraded`、`event: SKIP`），偏好抽取、向量检索等依赖 LLM/Embedding 的能力不可用。
- 修复：在 `memProject/.env` 填入两个 Key（DeepSeek 用于 LLM，硅基流动用于 bge-m3 Embedding）。

**② pgvector 扩展缺失**
- PostgreSQL 中 `vector` 扩展不可用（启动日志 warning：`extension "vector" is not available`）。
- 影响：向量列相关能力可能受限（当前建表时 `t_memory_vector` 未启用 vector 类型，非致命）。
- 修复：在 PostgreSQL 上安装 pgvector 扩展。

**③ Kafka / Redis 未运行**
- Kafka（localhost:9092）未启动，后端 `MQ Producer` 降级为不可用（非致命，服务正常）。
- Redis（localhost:6379）未配置/未运行，伪同步结果回调降级。
- 影响：高并发消息队列、异步结果回调暂不可用；当前单机演示无影响。

**④ Windows 时区库 tzdata（已修复）**
- 后端 `dashboard_service.py` 使用 `ZoneInfo("Asia/Shanghai")`，Windows 上 Python `zoneinfo` 默认无时区数据库，`admin/dashboard` 报 `ZoneInfoNotFoundError` → 500。
- 修复：后端 venv 安装 `tzdata`（`pip install tzdata`）后重启，dashboard 恢复 `code:0`。
- 注意：**测试服务器若为 Windows 环境，部署时也需安装 tzdata**。

## 八、待与老师确认的疑问清单

> 以下疑问供下次讨论时与老师确认，确认后需回填结论到本文件。

### Q1. 偏好分析的维度定义与粒度

- 会议举例为「颜色、型号、工艺」等维度，当前前端预设了 6 个维度（颜色/型号/工艺/材质/规格/服务方式），且支持多选。
- **疑问**：维度的定义是否应由后端统一维护（例如后端返回可选维度列表）？还是前端固定即可？不同业务场景（如物流 vs 电商）的偏好维度差异很大，是否需要按场景隔离维度？

### Q2. 偏好分析的后端接口契约

- 当前后端仅有记忆写入/检索/列表等接口，**没有偏好分析聚合接口**，前端用演示数据兜底。
- **疑问**：
  - 后端是否计划提供偏好分析接口（例如 `POST /api/v1/memory/preference-analysis`）？接口入参（用户/会话/任务范围 + 维度）和出参（维度 / 值 / 强度 / 置信度 / 支撑记忆）的契约如何定义？
  - 若短期内无法提供，前端演示数据兜底方案是否可接受？

### Q3. 实时监控看板的数据口径

- 当前首页看板直接复用 `/api/v1/admin/api-logs`（管理日志）在前端按时间桶聚合。
- **疑问**：
  - 看板应统计「所有接口调用」还是「记忆核心接口」？是否需要按接口路径分组？
  - 后端是否计划提供专门的看板聚合接口（如按小时/天/周返回频次+成功率），以减少前端聚合和分页限制？该接口是否需要管理员权限？

### Q4. 导入强制关联 Agent ID 的校验强度

- 当前实现：未配置 Agent ID 时**阻断导入**；文件内的 `agent_id` 字段优先于本地配置。
- **疑问**：是否需要更严格——例如**文件内每条记录必须携带 agent_id**，缺失即报错？还是「本地配置兜底 + 文件优先」即可？混合来源（部分记录有 agent_id、部分没有）时如何处理？

### Q5. 「注册与接入」是否需要独立菜单入口

- 当前实现为一页内 Segmented 切换两个操作。
- **疑问**：是否需要拆成两个独立菜单/路由（如「智能体注册」`/access/agents/register`、「智能体接入」`/access/agents/attach`）？会议原话「拆分为两个独立操作」，一页内分标签是否满足，还是必须独立导航？

### Q6. 分层记忆体系的层级归属

- 会议提出「短期与长期记忆分层机制，区分对话记录、历史会话与任务过程，任务 ID 由调用方传入，系统负责生成任务名称」。
- **疑问**：
  - 「短期/长期」分层在前端如何体现？当前前端按 user/session/task/agent 四层管理，是否需要增加「短期/长期」维度标签？
  - 「系统负责生成任务名称」——任务名称由后端生成，前端是否需要在导入时展示/确认生成的任务名称？

### Q7. 去重与冲突解决的展示
