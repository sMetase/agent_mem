## 〇、总体原则（来自老师的统一要求）

1. **功能边界整改（结构纠错）**：彻底拆分「记忆管理」与「分析提取」——记忆管理页只保留查询、浏览、增删改查；偏好维度选择、记忆提取分析等分析类功能全部迁出。
2. **交互逻辑重构**：作废「手动输入 ID」交互，统一改为「层级切换 + 列表联动勾选」模式。
3. **页面差异化**：多个功能页面避免高度模板化、样式雷同，针对每个模块业务属性做差异化设计。
4. **前后端对齐**：所有展示字段、接口参数、返回结构需与后端李国庆对齐确认。
5. **登录页最后做**，视觉与系统整体风格一致。
6. **数据说明**：分析类功能后端暂无专项接口，采用**前端演示数据兜底 + 动态字段兼容**，等后端接口就绪后无缝切换。

## 一、多层记忆管理模块整改（核心，工作量最大）

### 1.1 页面功能边界整改（强制）

- **现状**：[Memory/index.tsx](src/pages/Memory/index.tsx) 中混入了偏好分析面板（`PreferenceAnalysisPanel`），属于「分析类功能错放在记忆管理页」。
- **整改**：
  - 从记忆管理页**移除** `PreferenceAnalysisPanel`（用户偏好分析）及相关分析类 UI。
  - 记忆管理页仅保留：查询、列表浏览、勾选、新增改删（增删改查）。
  - 分析类功能统一迁移至「记忆生成与去重融合」（第 3 分区）下，见本文「二」。

### 1.2 交互逻辑重构：层级切换 + 列表联动勾选（强制）

- **作废**：原「手动输入 Session ID / Task ID」输入框（[Memory/index.tsx](src/pages/Memory/index.tsx) 中的 scope 搜索框）。
- **改为**：
  - 用户切换「用户级 / 会话级 / 任务级」标签（Segmented 或路由切换）后，下方列表**自动刷新**，展示对应层级的全部记忆。
  - 列表支持**单选、多选、跨条目组合勾选**（可跨不同会话、不同任务勾选组合，供后续分析使用）。
  - 移除「任务范围输入框」，列表勾选已覆盖该能力。

### 1.3 顶部搜索区 + 高级查询（强制）

- **基础搜索**：每个层级页面顶部统一配置关键词搜索框，支持按记忆内容、ID 等核心字段模糊检索。
- **高级查询**：搜索框旁增加「高级查询」入口，点击展开更多筛选条件（时间范围、标签、所属用户/会话等），筛选后列表同步刷新。

### 1.4 列表格式标准化（强制）

- 所有层级列表统一采用「核心信息列 + 操作列」结构。
- **操作列**：每条记忆末尾固定配置 **查看、修改、删除、更新** 四个操作按钮，全层级交互一致。

### 1.5 顶部新增层级统计（强制）

- **删除**页面中「当前搜索范围」「数据状态」等无价值提示文字。
- **新增**层级业务统计指标（在页面顶部 / 搜索区上方）：
  - 用户级：总记忆条数、活跃用户数、今日新增记忆数。
  - 会话级：总会话数、活跃会话数、今日新增会话数。
  - 任务级：总任务数、进行中任务数、已完成任务数。

### 1.6 各层级字段适配（仅字段不同，布局一致）

| 层级 | 列表核心字段 |
| --- | --- |
| **用户级** | 用户 ID、记忆内容摘要、记忆标签、创建时间、最后更新时间 |
| **会话级** | 会话 ID、所属用户 ID、会话主题摘要、关联记忆条数、创建时间、结束时间 |
| **任务级** | 任务 ID、所属会话 ID、任务主题、任务状态、关联记忆数、创建时间 |

> 三个层级遵循**完全一致的布局与交互**，仅列表展示字段、统计指标随层级属性适配，无单层级特殊定制。

### 1.7 技术实现要点

- **数据源**：真实接口 `listMemories`（`/api/v1/memory/list`）支持 `memory_scope`（user/session/task）、`session_id`、`task_id`、分页过滤。
- **当前路由**：`/memory/user`、`/memory/session`、`/memory/task` 已存在，复用同一组件按 `pathname` 区分层级（`getMemoryScope`）。
- **改动文件**：`src/pages/Memory/index.tsx`（主体重构）、`src/pages/Memory/components/MemoryFilterBar`（搜索 + 高级查询）、`src/pages/Memory/components/index.ts`（移除偏好面板导出）、`src/index.css`（样式）。

## 二、分析提取功能：迁移至「记忆生成与去重融合」并增强

### 2.1 定位（老师明确）

> 所有分析类功能（用户偏好提取、关键事实提取、关键实体人物生成等）统一遵循「选记忆 → 执行分析 → 展示结果」的标准流程。**这些分析在「3. 记忆生成与去重融合」都有对应的界面，分别在这里做。**

### 2.2 需改造的分析子功能

当前生成页已有预设：`用户偏好提取`、`关键事实提取`、`任务状态生成`、`历史决策沉淀` 等（见 [generation.ts](src/constants/generation.ts)）。

**本次新增/强化**：
1. **用户偏好提取**（已有，强化结果展示）：
   - 结果区展示**用户画像标签 + 多维度偏好分类结果**（颜色、型号、工艺等动态维度）。
   - 可复用后端 `POST /api/v1/memory/profile`（用户画像报告，返回 `preferences`、`business_focus`、`communication_style`、`decision_habits`、`project_background`、`personalization` 等字段）。
2. **关键事实提取**（已有，强化结果展示）：
   - 结果区以**条目列表**展示事实内容，可拓展**树形结构**呈现事实关联关系。
3. **关键实体人物生成**（**新增**）：
   - 新增「关键实体人物」预设视图，从选中记忆中提取关键实体与人物，展示实体/人物卡片或列表。

### 2.3 分析流程改造（强制）

- 作废「输入单条文本 → 提取」的旧逻辑，改为「**选记忆 → 执行分析 → 展示结果**」：
  - **选记忆**：用户先选择目标记忆范围（复用多层记忆管理页的层级筛选 + 列表勾选，或生成页内提供记忆选择器），分析仅基于选中的记忆集合。
  - **执行分析**：点击按钮触发对应分析。
  - **展示结果**：基于选中记忆生成结果。
- **动态字段兼容**：偏好维度由大模型基于选中记忆**动态生成**，字段不固定（本次可能有"性格"，下次可能无）。前端必须**动态渲染不固定的维度字段，不能写死字段名称**。
- **演示数据兜底**：后端暂无专项分析接口，先用前端演示数据 + 动态字段渲染，接口就绪后切换。

### 2.4 技术实现要点

- **改动文件**：`src/pages/Generation/index.tsx`（新增实体人物预设 + 选择记忆交互 + 差异化结果区）、`src/constants/generation.ts`（新增实体人物预设配置）、`src/pages/Memory/preference-analysis.ts`（偏好提取逻辑迁移/复用）、`src/index.css`（差异化样式）。
- **结果差异化**：偏好提取=画像标签/维度分类；事实提取=条目列表/树形；实体人物=实体卡片。避免三个页面样式同质化。

### 3.3 平台接入字段（依据《智能体接入接口.pdf》，梁闯已提供）

各平台接入方式与字段不同，表单按平台动态切换：

| 平台 | 接入方式 | 表单字段 | 拉取对话接口 |
| --- | --- | --- | --- |
| **Dify** | HTTP API | API Key、接口地址（api_base_url）、会话 ID（conversation_id） | `list-conversation-messages` |
| **Open WebUI** | HTTP API | API Key（Bearer）、接口地址、会话 ID、用户标识 | `GET /messages?conversation_id=&user=` 或 `/api/chats/{id}` |
| **阿里云 IMS** | SDK（AIChatEngine） | AccessKey/Secret、UserId、DeviceId、AgentId | `queryMessageList(startTime, endTime, pageNumber, pageSize)` |
| **智谱 BigModel** | HTTP API | Token、Agent ID、会话 ID | `POST /api/v1/agents/conversation` |

- **通用公共字段**：接入平台、采集模式（手动/定时）、采集频率（定时时）。
- **通用采集参数**：`user_id`（写入记忆系统时的归属用户）、`scene_id`。
- **改动文件**：`src/pages/AgentAccess/index.tsx`（平台选择 + 动态表单 + 采集配置）、`src/api/modules/agent.ts`（如有采集接口新增）、`src/api/types.ts`（接入/采集相关类型）、`src/constants/platform.ts`（新增：平台配置元数据，含各平台字段定义）。

### Q2 详细说明：分析功能在哪里"选记忆"？

分析功能（偏好提取/事实提取/实体生成）放在「3. 记忆生成与去重融合」页，但记忆数据在「2. 多层记忆管理」页。老师要求「选记忆 → 执行分析 → 展示结果」，"选记忆"这个动作发生在哪个页面，决定了是否需要全局共享勾选状态：

**方案 A：跨页传递（记忆页勾选 → 生成页分析）**
```
第2页 多层记忆管理            第3页 生成与去重融合
┌─────────────────┐           ┌─────────────────┐
│ ☑ 记忆A          │           │  使用记忆页勾选的 │
│ ☑ 记忆B          │ →跳转→    │  记忆A / 记忆B    │
│ ☐ 记忆C          │           │  [开始分析]       │
└─────────────────┘           └─────────────────┘
   先勾选                     后分析（读取勾选结果）
```
- 需 **Zustand 全局状态**存储被勾选记忆，两个页面共享。
- 缺点：跨页跳转，流程被拆成两步，用户易忘勾选过什么。

**方案 B：生成页内嵌选择器（同页完成）**
```
第3页 生成与去重融合
┌────────────────────────────────────────┐
│ ① 选记忆范围（内嵌记忆选择器组件）          │
│    层级:[用户|会话|任务]  [高级查询]        │
│    ☑ 记忆A  ☑ 记忆B  ☐ 记忆C             │
│ ② [执行分析]                             │
│ ③ 结果展示区                              │
└────────────────────────────────────────┘
```
- **无需**跨页共享状态。
- 做法：记忆选择器抽成通用组件 `MemorySelector`，记忆管理页用它做"列表+勾选"，生成页用它做"选记忆"，一处开发两处复用。

**推荐方案 B**：更符合老师描述的连续交互，且避免跨页状态耦合。

## 十一、界面差异化改造（0813 补充，已实施完成 ✅）

### 11.1 问题定位

- 老师指出：**生成与去重融合**（任务状态生成→低价值内容过滤 9 个预设）、**多信号融合检索**（6 模式）、**记忆上下文返回**（5 模式）的界面高度同质化——各子功能共用同一套模板，只是标题/参数不同，布局几乎无差异。
- **同质化的本质**：每个模块的多个子功能共享同一组件骨架，仅切换 `title`/`description`/参数，结果区全部是「表格 / 文本预览」同一形态。
- **明确边界**：统一前置流程（按层级选择记忆 → 勾选 → 触发分析）**属于规范的交互一致性，不属于同质化，保留**；需要差异化的是**结果展示区**。

### 11.2 设计原则

1. **保留统一前置流程**：选记忆（用户/会话/任务级）→ 勾选目标记忆 → 触发分析，三模块一致。
2. **结果区彻底差异化**：每个子功能按自身业务属性设计独立的结果展示形态，禁止共用同一模板。
3. **不改后端**：所有差异化基于现有返回结构（`MemoryGenerationDetail`、`MemoryItem`、`MemoryContextResult`），纯前端渲染层改造。
4. **交互一致、展示区分**：输入区保持稳定，结果区随功能切换形态。
