## 〇、背景与前置

- 后端已完成：write 改异步（Kafka 削峰）、存储抽象+去桥接表、关键词+hybrid 检索、generate 系列接口废弃、登录接口（login 即注册）等。
- 前端部分代码未同步，导致 405 / 类型不符 / 调用废弃接口 / 界面无意义。
- **身份走 Header 不走 body**：`client.ts` 拦截器已自动带 `X-API-Key` / `X-User-Id` / `X-Agent-Id`，后端从 Header 取身份。
- **AUTH_ENABLED**：后端默认 `false`（开发不鉴权），上线 `true` 前必须确认 apiKey 已保存。
- **记忆类型收敛为 5 类**：`fact` / `preference` / `task_state` / `process` / `correction`（旧的 `decision`/`constraint`/`feedback` 已废弃）。

- **#1 `/memory/list` 405 已修复**（本会话）：`listMemories` 方法由 GET 改回 POST，`tests/memory-list.test.ts` 断言同步改 POST。lint/test/build 通过。

## 三、额外工作

### 3.1 造数脚本对齐新契约

`scripts/seed-demo-data.py` 现有 49 条记忆用的 memory_type 含已废弃的 `decision`/`constraint`/`feedback`，需对齐 5 类：

| 旧类型 | 新类型 | 说明 |
|---|---|---|
| `decision` | `process` | 新 5 类中 process = 流程/方法论/决策/经验 |
| `constraint` | `fact` | 新 5 类中 fact = 业务对象/约束/确认事项 |
| `feedback` | `correction` | 新 5 类中 correction = 修正/反馈 |

### 3.2 与登录后 user_id 对齐

#13 完成后，登录返回的 `user_id` 由后端生成（如 `usr_xxx`），与 seed 数据所在 `user_001` 不同。为让登录后能看到演示数据，需把 seed 数据的 `user_id` 对齐到 login 返回的实际 user_id（实施时先实际登录一次取回 user_id，再调整 seed）。
