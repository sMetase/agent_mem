# 智能体记忆系统前端可用版本收敛修订方案

> 修订日期：2026-07-17  
> 适用分支：`feature/vilinno-fix`  
> 视觉基准：`docs/前端页面模板.jpg`  
> 接口基准：`docs/API接口文档-前端对接 .md`（2026-07-17 更新版）与当前 `/openapi.json`  
> 使用场景：导师评审演示  
> 修订目标：保留模板的七组导航、卡片和图标布局，删除不适合独立展示的说明型页面；保留生成、检索、上下文和监控能力，并把所有业务数据替换为真实接口数据。

## 1. 已确认的不可变约束

本方案不再采用“大幅压缩导航为六个一级菜单”的方向。以下内容已经明确，实施时不得偏离：

1. 系统最终用于导师评审，既要体现系统设计完整性，也要能够现场完成真实交互。
2. 模板中的七个编号分组全部保留，顺序和命名原则上不变。
3. “记忆生成与去重融合”必须保留，并在前端展示真实生成、去重、融合、更新、跳过和冲突结果。
4. “接口与监控”必须保留，健康状态、调用记录、耗时和错误必须来自真实接口。
5. 检索和上下文的所有子入口继续保留，但允许由同一个工作台按入口切换不同模式，避免复制多套页面。
6. 保留模板的卡片、图标、流程、颜色和仪表盘布局，只做必要的响应式和可用性修正。
7. 页面不得显示写死的业务指标、记录、告警、成功率或趋势；没有真实数据时显示空态，不使用模拟数据填充。

## 2. 核心修订结论

本轮真正需要删除的不是七个功能分组，而是以下两类内容：

- 只有“预计流程、接入状态、等待后端接口”说明，不能执行真实操作的独立能力说明页。
- 与其他页面完全重复、只是换了标题和路由的复制页面。

导航收敛方式采用“保留分组和必要子入口，减少独立页面数量”：

- 七组导航继续存在。
- 检索、上下文、生成的多个子入口保留，但进入共享工作台，并通过 Query 参数或页内标签切换预设条件、结果过滤方式和说明。
- 用户级、会话级、任务级记忆继续保留子入口，但复用同一记忆管理页，并自动带入对应范围筛选。
- 不再让菜单项跳转到通用 `CapabilityGuide` 说明页。
- 总览、生成、检索、上下文、监控的视觉结构继续参考模板，不重新设计另一套后台框架。

## 3. 后端实测基线

2026-07-17 已使用隔离测试用户完成真实联调，当前后端具备前端收敛所需的大部分能力。

| 能力 | 实测状态 | 关键事实 |
| --- | --- | --- |
| 健康、OpenAPI、CORS | 通过 | `/health`、`/openapi.json` 返回 HTTP 200，开发来源预检通过 |
| 场景 | 通过 | 创建、详情、更新、列表、停用均可用 |
| 智能体 | 通过 | 注册、详情、更新、列表、停用均可用，注册返回一次性 API Key |
| 会话 | 通过 | 创建、详情、列表、关闭均可用 |
| 任务 | 基本通过 | 创建、详情、进度、列表、更新、完成均获得过成功响应，但出现过间歇性超时 |
| 记忆写入 | 通过 | 一次输入可能生成多条记忆，返回 `ADD/SKIP/MERGE` 结果 |
| 同步生成 | 已实现 | `POST /memory/generate`，输入单段文本并返回完整去重决策和逐条明细 |
| 批量生成 | 已实现 | `POST /memory/generate/batch`，支持 1 至 50 条文本，每条独立执行完整流水线 |
| 异步生成 | 已实现 | `POST /memory/generate/async`，立即返回 `request_id/status/message` |
| 生成状态 | 已实现并完成只读探测 | `GET /memory/generate/{request_id}/status` 返回真实 `status/progress/result/error`；不存在的 ID 返回 `not_found` |
| 记忆列表 | 通过 | 返回 `{ items,total,page,page_size }` |
| 记忆检索 | 通过 | 返回真实结果，但 `relevance_score` 可能为 `null` |
| 上下文 | 通过 | 返回 `formatted_text/fragments/memory_count/estimated_tokens` |
| 记忆更新 | 通过 | 返回版本递增结果 |
| 单条删除 | 文档与运行结果不一致 | 最新文档标记已实现，但实测仍返回 HTTP 500，最近复现 `trace_id=3cb19899d8784ec0`，发布前必须复验 |
| 清空用户记忆 | 通过 | 返回真实 `deleted_count` |
| 后台统计与日志 | 通过 | `admin/stats`、API 日志、检索日志、全量记忆均返回真实数据 |

结论：前端可以立即开始真实数据改造；单条删除需要后端修复，间歇性超时需要前端提供明确状态和手动重试。

## 4. 七组导航的保留与修订方案

### 4.1 智能体接入与记忆数据写入

分组、顺序和现有子入口保留。

| 子入口 | 处理 | 页面行为与真实接口 |
| --- | --- | --- |
| 智能体注册接入 | 保留 | 调用 `POST /api/v1/agent/register`，成功后只展示一次完整 API Key，并回填配置 |
| 场景标识配置 | 保留 | 使用场景创建、列表、详情、更新、停用接口，支持从真实列表选择 |
| 接口密钥配置 | 保留 | 展示本地 Agent ID/API Key 配置，列表只显示后端返回的掩码前缀 |
| 对话记录写入 | 保留 | 调用 `memory/write`，展示真实 `ADD/SKIP/MERGE` 数量和记忆 ID |
| 历史会话导入 | 保留 | 复用写入页的 `session` 模式，写入前校验会话字段 |
| 任务过程写入 | 保留 | 复用写入页的 `task_process` 模式，并提供进入真实任务管理页的操作 |
| 数据校验与标准化 | 保留 | 属于前端适合展示的导入前校验；只展示本地解析结果，不伪装为后端处理结果 |

数据校验可以继续作为独立子入口，因为它是用户上传数据前的明确任务，不属于后端内部算法。

### 4.2 通用记忆建模与多层记忆管理

保留编号分组以及用户级、会话级、任务级三个核心入口，删除没有真实操作的独立说明页。

| 当前子入口 | 处理 | 落地方式 |
| --- | --- | --- |
| 记忆单元建模 | 删除独立页面和菜单入口 | 记忆字段结构属于后端契约，在记忆详情抽屉中展示真实字段即可 |
| 记忆类型管理 | 删除独立页面和菜单入口 | 当前没有类型字典 CRUD；类型作为记忆页筛选和编辑字段存在 |
| 记忆状态管理 | 删除独立页面和菜单入口 | 状态筛选与修改合并到记忆管理页 |
| 元数据管理 | 删除独立页面和菜单入口 | 场景、任务、会话、标签等进入记忆详情和编辑表单 |
| 用户级记忆 | 保留子入口 | 进入共享记忆页，预设用户范围与偏好、事实、约束类型 |
| 会话级记忆 | 保留子入口 | 进入共享记忆页，突出 Session ID 筛选和会话来源 |
| 任务级记忆 | 保留子入口 | 进入共享记忆页，突出 Task ID 筛选并链接任务进度 |
| 智能体级记忆 | 暂时删除独立入口 | 当前后端不支持按 Agent ID 完整分页查询；待接口明确后恢复 |

删除以上说明页不会改变第二分组的存在，也不会删除真实的多层记忆管理能力。

### 4.3 记忆生成与去重融合

编号分组必须保留，现有子入口名称也保留，但不再进入九个 `CapabilityGuide` 说明页。所有入口进入一个真实的“生成与去重融合工作台”。

| 子入口 | 工作台预设或结果视图 |
| --- | --- |
| 用户偏好提取 | 默认勾选 `preference`，结果筛选偏好记忆 |
| 关键事实提取 | 默认勾选 `key_fact`，结果筛选事实记忆 |
| 任务状态生成 | 默认勾选 `task_state`，显示 Task ID 关联字段 |
| 历史决策沉淀 | 默认勾选 `decision`，结果筛选决策记忆 |
| 冲突检测 | 展示本次真实 `conflict_count` 和 `action=conflict` 明细 |
| 冲突记忆去重 | 展示后端返回的冲突处理、更新或跳过结果，不提供虚构的人工裁决 |
| 相似记忆去重 | 展示 `merge/discard/update_existing` 等真实决策 |
| 记忆融合管理 | 展示融合前后内容摘要、目标记忆 ID 和处理结果；字段不存在时明确为空 |
| 低价值内容过滤 | 展示 `discard/SKIP` 数量和后端返回的原因；没有原因字段时不自行编造 |

#### 4.3.1 三种真实执行模式

工作台应提供“同步生成、批量生成、异步生成”三种真实模式，不再把异步能力列为未来规划。

| 模式 | 接口 | 使用场景 | 前端交互 |
| --- | --- | --- | --- |
| 同步生成 | `POST /api/v1/memory/generate` | 单段文本、需要立即查看结果 | 提交后等待 5 至 15 秒，禁止重复提交，完成后直接展示结果 |
| 批量生成 | `POST /api/v1/memory/generate/batch` | 历史数据迁移、批量测试 | 1 至 50 条、每条不超过 10000 字符；展示总体统计和每条输入结果 |
| 异步生成 | `POST /api/v1/memory/generate/async` | 长文本或不希望阻塞页面 | 立即保存 `request_id`，轮询状态接口并展示真实总体进度 |

同步和异步请求共用以下字段：`text/user_id/agent_id/scene_id/session_id/task_id/extraction_types/source_record_ids/metadata`。批量请求使用 `texts`，并共用身份、场景、会话、任务和抽取类型。

批量接口是同步请求，文档明确总耗时会随文本数增长，且没有中间进度。前端应提示预计耗时、为批量请求设置独立长超时，并在导师演示默认建议 2 至 5 条；接口上限仍保持 50 条。同步、批量请求超时后不得自动重放，因为服务端可能已经写入部分或全部记忆。

抽取类型严格使用最新契约：`key_fact/task_state/decision/preference/process/feedback`。生成结果中的 `memory_type` 可能使用 `fact/task/preference/decision/constraint`，前端显示层需要同时兼容 `task` 与 `task_state`，不能把请求类型枚举直接当成结果类型枚举。

#### 4.3.2 同步与批量结果展示

同步生成结果直接映射：

- `memory_ids`：本次实际存储的记忆 ID。
- `new_count`：新增数量。
- `merged_count`：合并数量。
- `discarded_count`：高重复丢弃数量。
- `updated_count`：更新已有记忆数量。
- `conflict_count`：冲突数量。
- `details`：逐条处理明细。

`details[].action` 使用严格枚举：

| action | 前端文案 | 结果表现 |
| --- | --- | --- |
| `keep_new` | 新增 | 绿色标签，展示新 `memory_id` |
| `merge` | 合并 | 蓝色标签，展示目标记忆 ID 和后端 message |
| `discard` | 跳过 | 灰色标签，展示重复或低价值原因 |
| `update_existing` | 更新 | 处理中标签，展示被更新的记忆 ID |
| `conflict` | 冲突 | 警告标签，展示后端返回的冲突说明 |

明细表展示 `content_preview/memory_type/importance/confidence/memory_id/message`。字段为 `null` 或缺失时显示“-”，不得自行生成原因、融合前内容或冲突详情。

批量结果需要同时展示：

- 总体 `total_memories/total_new/total_merged/total_discarded`。
- 通过各条 `results` 汇总 `updated_count/conflict_count`，因为最新批量响应没有单独的 `total_updated/total_conflict` 字段。
- 每条输入的序号、输入摘要、处理计数和 details；单条失败不得覆盖其他已完成结果。

#### 4.3.3 异步状态轮询

异步提交返回 `request_id/status/message`，随后调用：

`GET /api/v1/memory/generate/{request_id}/status`

状态处理规则：

| status | 页面状态 | 行为 |
| --- | --- | --- |
| `pending` | 排队中 | 显示队列状态和 `progress`，继续轮询 |
| `processing` | 处理中 | 将后端 0 至 1 的 `progress` 格式化为 0% 至 100%，继续轮询 |
| `completed` | 已完成 | 停止轮询，将 `result` 按同步生成结果展示 |
| `failed` | 失败 | 停止轮询，展示 `error`，保留原始输入供用户修改后重试 |
| `not_found` | 已过期或不存在 | 停止轮询，说明结果可能已超过 30 分钟缓存期 |

轮询建议从 1 秒开始，稳定处理阶段使用 2 秒间隔；页面卸载、进入终态或达到前端最大等待时间后停止。当前接口没有取消任务能力，前端不得展示“取消”按钮。`request_id` 可保存到当前页面状态或 `sessionStorage`，用于同一浏览器刷新后在 30 分钟有效期内恢复查询。

后端当前最多执行 5 个并发异步任务，超额任务进入队列。前端需要在提交响应中显示后端 `message`，但不能根据该文本自行维护队列数量。

#### 4.3.4 流程卡片与进度真实性

工作台保留模板中的五段处理流程卡片，但当前异步接口只提供一个总体 `progress`，没有逐阶段进度。因此：

- 未执行时，五张流程卡显示中性状态，不显示 100%。
- 同步或批量接口返回前，只显示页面级加载状态，不逐张模拟进度。
- 异步任务使用一个真实总体进度条，不把同一个 `progress` 重复伪装成五个阶段的完成比例。
- `completed` 后可将整个流程标记为完成，统计与明细全部来自 `result`。
- 只有后端未来返回阶段状态数组时，才显示每个阶段的独立进度。

### 4.4 多信号融合记忆检索

编号分组和五个子入口全部保留，继续复用一个检索工作台。

| 子入口 | 工作台差异 |
| --- | --- |
| 语义向量检索 | 默认突出 Query、Scene、类型和相关度结果 |
| 关键词检索 | 保留关键词入口；后端需返回实际采用的检索信号，前端不得仅换标题假装使用独立算法 |
| 元数据过滤 | 自动展开类型、状态、场景、任务、会话和时间筛选 |
| 融合排序 | 默认开启 `rerank`，展示后端返回的综合分数与信号说明 |
| Top-K 返回 | 自动聚焦 `top_k` 和结果数量，仍调用真实搜索接口 |

需要补齐检索接口的可解释字段。建议在请求中增加可选 `retrieval_mode`，在响应中增加 `applied_signals` 和可选 `score_breakdown`。如果本轮无法修改后端，前端统一标注“由后端执行多信号检索”，不承诺某个子入口一定只使用单一算法。

### 4.5 记忆上下文返回

编号分组和四个子入口全部保留，继续复用一个上下文工作台。

| 子入口 | 工作台差异 |
| --- | --- |
| 结构化 JSON 返回 | 默认展示真实 `fragments/memory_count/estimated_tokens` JSON |
| 文本上下文片段返回 | 默认展示真实 `formatted_text`，提供复制操作 |
| 相关性筛选 | 展开查询、记忆类型、任务和会话条件 |
| 长度控制与压缩 | 聚焦 Token 预算、长度参数和实际估算 Token 数 |

同一次上下文请求可以在 JSON 与文本视图间切换。`fragments.length` 不保证等于 `memory_count`，前端不能根据数组长度自行改写统计值。

### 4.6 接口与监控

编号分组和三个子入口全部保留，删除固定的接口状态、固定耗时、固定告警和固定“待处理问题 4”。

| 子入口 | 真实数据来源 |
| --- | --- |
| 接口健康检查 | `/health`，展示实时状态、应用名、版本和本次请求耗时 |
| 调用状态监控 | `GET /api/v1/admin/api-logs`，展示接口路径、方法、状态码、错误码、耗时和时间 |
| 联调记录 | `GET /api/v1/admin/retrieval-logs` 与失败 API 日志，展示真实请求记录和错误 trace_id |

监控页不承担 CPU、内存、磁盘、数据库连接池等基础设施监控。没有对应接口的指标不出现在页面中。后台日志未来应加管理员权限；前端对 HTTP 401/403 提供明确权限空态。

### 4.7 系统设置

编号分组和两个子入口保留。

- 基础连接设置：Base URL、连接测试、服务版本。
- 本地用户身份：User ID、Scene ID、Agent ID、API Key。
- 所有配置继续通过 Zustand Store 和统一存储工具保存，不允许页面散落调用 `localStorage`。
- Agent 与 Scene 的创建和选择可从接入页回填，不重复维护第二套数据。

## 6. 首页真实数据改造

首页继续保持模板的五张指标卡、功能流程、三列业务面板、趋势图、环形图、占比图和最近告警布局，但所有数值必须来自接口。

### 6.1 五张指标卡

| 模板卡片 | 真实数据来源 | 无数据时处理 |
| --- | --- | --- |
| 接入智能体 | Agent 列表的 `total` | 显示 0，不显示伪造环比 |
| 业务场景 | Scene 列表的 `total` | 显示 0 |
| 记忆总量 | `admin/stats.total_memories` | 显示 0 或权限空态 |
| 今日检索调用 | 24 小时检索日志的 `total` | 显示 0 |
| 上下文返回成功率 | 新增 Dashboard 聚合接口 | 暂无聚合时显示“暂无统计”，不能固定为 99.2% |

保留卡片图标、颜色和布局。只有后端返回对比数据时才显示“较昨日”；没有时间序列时将副文案改成“实时统计 · 更新时间”。

### 6.2 首页其他面板

- 功能总览：属于产品流程说明，可以保留静态文字，但不得混入伪造业务数字。
- 智能体接入与数据写入：使用真实 Agent 列表和最近写入时间。
- 多层记忆管理：使用完整聚合接口返回的类型数量和比例；不得用当前分页数据推导全库分布。
- 生成与去重融合：页面内展示当前请求的真实生成、融合、更新、跳过和冲突数量；首页“今日”统计仍需 Dashboard 聚合接口，不能用当前浏览器最后一次请求冒充全局数据。
- 多信号融合检索：展示最近真实检索记录或最近一次用户检索结果。
- 上下文返回预览：展示当前浏览器最近一次真实上下文结果；未执行时显示引导空态。
- 记忆增长趋势：使用后端按天聚合结果，并增加时间点悬停明细。
- 记忆类型分布：使用后端全量聚合结果。
- 检索方式占比：只有后端能区分检索信号时才展示比例，否则显示“后端暂未提供信号统计”。
- 最近告警与任务：使用失败 API 日志和真实任务列表，不再写死告警。

## 7. Dashboard 聚合接口方案

当前 `/api/v1/admin/stats` 只返回记忆、用户、智能体和会话总数，不能支持模板全部图表。为避免前端拉取全量分页数据后自行聚合，建议新增：

`GET /api/v1/admin/dashboard?hours=24&trend_days=7`

建议响应：

接口约束：

- `generation_summary` 是后端按所选时间范围聚合的全局数据；同步、批量和异步生成响应只代表单次任务，不能替代该统计。

如果后端暂时不能新增该接口，第一阶段只展示现有接口能够证实的总量和列表，其余图表保留版面并显示“暂无统计”，不得从分页样本推导全量结论。

## 11. 发布验收标准

### 导航与模板

- 七个编号分组全部存在，顺序与模板一致。
- 生成、监控、检索、上下文及其要求保留的子入口全部可访问。
- 页面继续使用模板的卡片、图标、流程和图表语言，无整体重构痕迹。

### 数据真实性

- 源码中不存在运行时业务假指标、假记录、假告警和假成功率。
- 每个业务数字都能定位到接口响应字段。
- 无数据、无权限、后端异常和超时均有明确状态，不回退到演示数据。
- 分布和比例只由后端全量聚合结果产生，不使用当前页数据推算。

### 功能闭环

- 接入、三类写入、生成、记忆管理、五类检索入口、四类上下文入口和三类监控入口均能使用真实接口。
- 生成页可以展示真实新增、融合、更新、跳过和冲突结果。
- 同步生成、1 至 50 条批量生成、异步提交和状态轮询均与最新接口契约一致。
- 异步任务在 `completed/failed/not_found` 时停止轮询；完成结果与同步结果使用同一套展示组件。
- 页面只显示异步接口提供的总体 `progress`，不伪造五个处理阶段的独立进度。
- 监控页可以展示真实健康状态、API 日志、检索日志和错误 trace_id。
- 单条删除 HTTP 500 修复并复验前，不得判定整体发布通过。

### 评审体验

- 评审演示过程中不需要解释“这是 Mock 数据”或“这个页面只是一份功能说明”。
- 所有保留的入口都有真实内容、真实交互或明确空态。
- 1280px 及以上评审屏幕不出现卡片裁切、操作按钮不可见和页面横向溢出。

## 12. 最终决策摘要

本轮不是重新设计导航，而是在模板既有信息架构中完成真实性收敛：

- 保留七组导航、生成、监控、检索和上下文子入口。
- 删除记忆建模、类型字典、状态字典、元数据模板、智能体级记忆等没有真实管理接口的独立说明页。
- 多个子入口可以共用真实工作台，但必须带入不同预设并展示可验证的结果。
- 生成工作台使用已实现的同步、批量、异步和状态查询接口，不再将异步处理写成未来能力。
- 保留模板布局，删除所有写死数据；模板缺少的聚合数据通过 Dashboard 接口补齐。
- 后端接口暂缺时展示空态，不以 Mock 维持视觉完整。

完成后，前端仍然保持导师熟悉的模板结构和系统功能全貌，但每个保留页面都能执行真实任务、展示真实结果或清楚说明当前无数据，不再出现“功能树被直接当成页面”的问题。
