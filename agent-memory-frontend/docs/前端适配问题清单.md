## 〇、先读这个：后端本轮已落地改动（前端对接前必看）

以下后端改动已全部完成，前端修改时可直接使用这些接口能力：

| 后端改动 | 前端对接影响 |
|---------|-------------|
| `list` 接口新增 `agent_id`/`memory_type`/`time_start`/`time_end` 过滤 | 用户级/多层记忆查询用 `POST /memory/list` 即可，参数见下 |
| `Scene` 加 `user_id`（场景私有） | 场景列表按当前用户过滤 |
| `Session` 加 `title` 字段 | 会话列表返回 `title`，直接展示 |
| `agent_list` 支持按 user 过滤 | 前端拿「当前用户 agent 下拉」直接调 `GET /agent`（带 X-User-Id header） |
| 四个列表接口 `user_id` 统一 **header 派生** | ⚠️ 前端**不要**再传 `?user_id=` query 参数，改传 `X-User-Id` header |
| `agent_register` / `scene_create` 加同名校验 | 同名会返回 **409**，前端要弹提示「已存在同名智能体/场景」 |
| 记忆类型统一为 5 类 | `fact / preference / task_state / process / correction` |

**鉴权提醒**：当前服务 `AUTH_ENABLED=true`，所有接口需带 `X-API-Key` header；用户维度用 `X-User-Id` header 标识（不是 query 参数）。

## 四、UI/UX 问题与具体改法

### 1. 场景停用后无法再启用

**改法**：场景列表对 `is_active=false` 的场景显示「启用」按钮，调 `PUT /scene/{scene_id}`，body `{is_active: true}`。

### 2. 秘钥展示错误

**改法**：
- 注册智能体成功（`POST /agent/register` 返回 `api_key`）后，**弹 Modal** 展示 `agentId` + `apiKey` 明文 + 复制按钮 + 「仅显示一次，请妥善保存」提示，关闭后不再可见。
- **删除「接口秘钥配置」页面**。

### 3. 缺智能体列表

**改法**：新增「智能体管理」页面：
- 调 `GET /agent`（带 `X-User-Id` header）拿列表
- 表格列：智能体名称、所属场景、状态（启用/停用）、API Key 前缀（脱敏 `mem_****`）、创建时间
- 操作：启用/停用（`PUT /agent/{id}`）、换 key（`POST /agent/{id}/rotate-key`，新 key 弹窗显示一次）
- 支持按场景下拉过滤

### 4. 记忆数据导入（含数据清洗约定）

导入界面保留「历史会话导入」，弃置「对话记录/任务过程」入口。

**数据清洗由其他人完成**，前端只接收清洗后的 JSONL（每行一个会话）：

| 字段 | 必填 | 类型 | 说明 |
|------|------|------|------|
| `messages` | 是 | array | `{role, content}` 两项 |
| `session_summary` | 否 | string | 会话摘要 |
| `session_time` | 否 | string | ISO 8601 |
| `session_source` | 否 | string | 来源 |

`role` 合法值：`user/assistant/system/tool/agent`；`content` 纯文本去掉一切元数据。

**导入界面**：agent 下拉框 + 文件上传 + 模板下载；解析 JSONL 逐条调 `POST /memory/write`（`interaction_type=session`，`session_id` 前端自动生成）。

### 5 & 6. 用户级 / 多层记忆查询（统一改法）

**核心**：多层记忆管理（用户/会话/任务/智能体四级）**不用 `search`（相似度检索），改用 `POST /memory/list`（结构化查询）**。

**筛选控件**：时间范围选择器 + 记忆类型下拉（`memoryTypeOptions`）+ 场景下拉 + 智能体下拉。

**去掉**：user_id 输入框、「活跃用户数」指标、语义搜索框。

**list 接口参数**：

| 参数 | 说明 |
|------|------|
| `user_id` | 从 `X-User-Id` header 自动带，前端不用传 |
| `scene_id` / `agent_id` | 场景/智能体下拉选中后传 |
| `memory_type` | 记忆类型下拉选中后传 |
| `time_start` / `time_end` | 时间范围，ISO 8601 |
| `page` / `page_size` | 分页 |

**四层入口统一「名称下拉/列表点选」，用户不接触原始 id**：

| 层级 | 下拉数据来源 | 选中后传 |
|------|-------------|---------|
| 场景 | `GET /scene` | `scene_id` |
| 智能体 | `GET /agent` | `agent_id` |
| 任务 | `GET /task`（有 title） | `task_id` |
| 会话 | `GET /session`（有 title） | `session_id` |

### 7. 记忆画像

已实现，展示 `persona` 文本即可。雷达图暂不做（当前仅返回文本，结构化后续再改）。

### 8. 多信号融合（检索）界面

**改法**：
- **状态下拉**：后端 status 实际是 `active/pending/deleted`，检索默认只查 active。前端去掉三态筛选，或简化为「有效/已删除」两档（默认有效）。
- **场景下拉**：从 `GET /scene` 拉取做下拉框，选中传 `scene_id`。
- **返回数量**：`top_k` 改成 InputNumber 可输入（1-50，默认 10）。

### 9. 记忆上下文返回（四界面合一）

**改法**：合并为一个页面，控件 = `query 输入框 + top_k 数字 + 场景下拉 + agent 下拉 + 返回按钮`，调 `POST /memory/context`。

**去掉**：四个 tab、taskId 手写框、status 筛选、「按类型分组/平铺」开关（`group_by_type` 用后端默认值 `true` 即可）。

## 五、补充规则

### 1. 智能体/场景重名（后端已加校验）
同一场景不能注册同名智能体、同一用户不能创建同名场景。前端调接口返回 409 时弹「已存在同名」提示即可，后端已处理。

### 2. 秘钥显示
只弹窗显示一次（见问题 2）。

### 3. 监控范围
监控 = 后端实际提供的全部接口（含 `/health`、`/admin/*`、`/monitor/stats`、`/proxy/*`），**不监控后端没提供的接口**（如废弃的 `/memory/generate`）。

### 4. health 与联调记录
- `GET /health` 是服务存活探活，不是「接口健康检查」。
- 联调记录 = `/admin/api-logs`（接口调用日志）+ `/admin/retrieval-logs`（检索日志），联调排查用。
