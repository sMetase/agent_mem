# 开发流程说明

当前前端由项目负责人统一开发和维护。这份文档用于约定目录职责、功能方向和集成流程，不再按人员划分业务模块。产品定位是“智能体记忆管理控制台”，不包含实时 AI 对话。

## 目录职责

- `src/pages`：各项产品功能页面，按业务能力独立组织。
- `src/router`：路由注册、页面入口和菜单元信息。
- `src/layouts`：控制台整体布局，不堆放具体业务逻辑。
- `src/store`：跨页面共享状态，局部页面状态不应随意提升到全局。
- `src/api`：请求客户端、统一错误处理、数据类型和业务接口模块。
- `src/components/common`：通用页面容器、加载、空状态、异常和确认组件。
- `src/components/business`：可跨页面复用的业务组件。
- `src/utils`：配置、导入解析、存储和格式化等无界面工具。

页面不应绕过 `src/api/request.ts` 单独创建 Axios 客户端。新增页面入口时，应同步更新路由和菜单配置；修改公共状态或接口类型时，应检查所有相关页面。

## 分支与 PR 流程

1. 从最新 `dev` 创建 `feature/*` 分支。
2. 只修改本次功能相关内容，并及时同步 `dev`。
3. 提交前运行：

```bash
corepack pnpm check
```

4. 创建目标为 `dev` 的 Pull Request。
5. PR 描述写清改动、公共层影响、后端依赖和验证结果。
6. 完成代码检查和集成验证后合并。
7. 里程碑稳定后，再由 `dev` 合并到 `main`。

## 接口与演示数据

- 写入、列表、搜索、上下文、任务和健康检查应通过 `src/api` 使用真实接口。
- 后端暂未提供的聚合统计可以使用演示数据，但页面必须明确其展示性质。
- 接口字段变化应先更新 `src/api/types.ts` 和对应模块，再调整页面。
- 不要为了适配单个页面复制一套响应解析逻辑。

## 合并前检查

- 没有混入与本次功能无关的文件或测试数据。
- 没有重新引入实时聊天功能。
- 页面在桌面端和移动端均可访问。
- 空状态、加载状态和错误状态可见。
- `corepack pnpm check` 全部通过。
