# 智能体记忆系统前端部署说明

> 说明：本文档用于说明前端如何从代码构建并部署到服务器。若部署环境由后端服务器统一托管，需要部署同学根据实际 nginx、端口和域名配置调整。

## 1. 部署目标

前端部署后，用户可以通过浏览器访问记忆系统控制台，并由前端页面请求后端接口完成记忆写入、检索、管理、生成、上下文返回和监控。

推荐部署形态：

```text
浏览器
  ↓
前端静态页面服务 nginx
  ↓
后端 API 服务 http://120.27.207.238:8000 或实际后端地址
```

如果前端和后端部署在同一台服务器，也可以由 nginx 同时负责：

- 托管前端构建产物。
- 将 `/api` 转发到后端服务。
- 将 `/health` 转发到后端健康检查接口。
- 配置 HTTPS 证书。
- 将 HTTP 请求重定向到 HTTPS。

## 2. 环境要求

服务器或构建机器需要：

- Node.js。
- Corepack。
- pnpm，项目中声明版本为 `pnpm@11.7.0`。
- nginx 或其他静态资源服务器。

本地或服务器构建前建议执行：

```bash
corepack enable
corepack pnpm install
corepack pnpm check
corepack pnpm build
```

其中 `check` 会依次运行：

- `pnpm lint`
- `pnpm test`
- `pnpm build`

## 3. 环境变量

前端主要使用以下环境变量：

| 变量 | 说明 | 示例 |
| --- | --- | --- |
| `VITE_API_BASE_URL` | 默认后端服务地址 | `http://120.27.207.238:8000` |
| `VITE_API_TIMEOUT_MS` | 请求超时时间，单位毫秒 | `30000` |
| `VITE_APP_TITLE` | 页面标题 | `智能体记忆系统前端` |

开发环境可使用 `.env.development`。

生产环境建议创建或确认 `.env.production`，示例：

```env
VITE_API_BASE_URL=https://你的后端域名
VITE_API_TIMEOUT_MS=30000
VITE_APP_TITLE=智能体记忆系统前端
```

如果前端和后端同域部署，并由 nginx 转发 `/api` 和 `/health`，也可以将 `VITE_API_BASE_URL` 设置为空或设置为同源地址。具体以部署方案为准。

## 4. 构建步骤

进入项目根目录：

```bash
corepack enable
corepack pnpm install
corepack pnpm build
```

构建成功后会生成：

```text
dist/
```

该目录就是前端静态部署产物。

## 5. nginx 静态部署示例

假设前端构建产物放在：

```text
/var/www/agent-memory-frontend/dist
```

nginx 示例配置：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /var/www/agent-memory-frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /health {
        proxy_pass http://127.0.0.1:8000/health;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

如果后端不在同一台机器，请将 `127.0.0.1:8000` 改为实际后端地址。

## 6. HTTPS 配置建议

如果老师或浏览器要求 HTTPS，部署同学需要在 nginx 中配置证书。

HTTPS 部署后建议：

- 前端访问地址使用 `https://...`。
- 后端接口也尽量通过 HTTPS 暴露。
- 如果前端是 HTTPS，而后端仍是 HTTP，浏览器可能拦截请求，出现 mixed content 问题。
- 推荐通过 nginx 统一转发，让浏览器只访问 HTTPS 域名。

常见 HTTPS 结构：

```text
https://your-domain.com
  ├─ 前端页面
  ├─ /api/*    → 后端 API
  └─ /health   → 后端健康检查
```

## 7. 线上验证流程

部署完成后建议按以下顺序检查：

1. 打开前端首页，确认页面不是空白。
2. 刷新任意子页面，例如 `/monitoring/health`，确认不会 404。
3. 打开“系统设置”，确认 Base URL 配置正确。
4. 打开“接口健康检查”，点击刷新数据。
5. 如果健康检查返回正常，继续测试记忆写入。
6. 导入一条测试记忆。
7. 打开记忆管理页刷新列表，确认能看到刚写入的数据。
8. 打开检索页，输入与刚写入内容相关的问题，确认能检索到结果。
9. 打开上下文返回页，确认可以得到 JSON 或文本上下文。
10. 打开接口监控页，确认能看到调用日志或状态信息。

## 8. 常见问题

### 8.1 页面能打开，但接口健康检查显示状态未知

可能原因：

- `/health` 没有转发到后端。
- 后端 `/health` 返回格式和前端预期不一致。
- 前端系统设置中的 Base URL 配置错误。
- HTTPS 页面请求 HTTP 接口被浏览器拦截。

建议排查：

- 浏览器直接访问 `http://后端地址/health` 或 `https://域名/health`。
- 确认返回中包含 `status`、`app`、`version` 等信息。
- 检查 nginx 是否正确转发 `/health`。

### 8.2 页面子路由刷新后 404

这是前端单页应用常见问题。nginx 需要配置：

```nginx
try_files $uri $uri/ /index.html;
```

### 8.3 本地可以请求，线上请求失败

可能原因：

- 后端没有配置跨域。
- nginx 转发路径错误。
- 前端使用了错误的 Base URL。
- HTTPS 和 HTTP 混用。

建议优先采用同域代理方式，即前端请求 `/api` 和 `/health`，由 nginx 转发到后端。


## 9. 部署分工建议

前端负责人：

- 提供构建产物。
- 确认环境变量。
- 确认页面和接口调用逻辑。
- 配合验证页面功能。

部署负责人：

- 安装运行环境。
- 配置 nginx。
- 配置 HTTPS。
- 配置 `/api` 和 `/health` 反向代理。
- 确认服务器防火墙和端口开放。

后端负责人：

- 提供稳定 API 服务。
- 确认接口返回格式。
- 处理跨域或代理后的请求头。
- 提供健康检查和管理统计接口。
