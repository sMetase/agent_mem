# 前端可用版本收敛实施计划（智能体执行版）

> 生成日期：2026-07-17  
> 工作分支：`feature/vilinno-fix`  
> 目标分支：`dev`  
> 面向对象：编码智能体、代码模型、自动化执行器  
> 产品方案：`docs/前端可用版本收敛修订方案.md`  
> 接口基准：`docs/API接口文档-前端对接 .md` 与当前 `/openapi.json`  
> 视觉基准：`docs/前端页面模板.jpg`

## 1. 执行目标

在不大改模板导航和视觉骨架的前提下，将当前前端收敛为可用于导师评审的真实可用版本：

1. 七个编号导航分组全部保留，顺序不变。
2. 生成与去重融合、接口与监控完整保留。
3. 检索五个子入口、上下文四个子入口全部保留。
4. 删除只有能力说明、没有真实操作的独立页面。
5. 页面业务数据全部来自真实接口；没有数据时展示空态，不回退到 Mock。
6. 保留模板卡片、图标、流程和图表风格，修复裁切、拥挤和响应式问题。
7. 建立可演示的真实链路：接入 → 写入 → 生成 → 记忆管理 → 检索 → 上下文 → 监控。

## 2. 本轮明确不处理

- 单条记忆删除问题暂不处理。它属于后端问题，不修复、不重复探测、不新增相关测试，也不作为本轮发布阻塞条件。
- 不重做 React Router、App Shell、Zustand 或 Axios 请求基础架构。
- 不引入第二套请求层、第二个状态库或新的 UI 组件库。
- 不建设 CPU、内存、磁盘、数据库连接池等基础设施监控。
- 不实现聊天回复生成、Chat 页面或完整账号登录体系。
- 不使用分页列表在前端推导全库比例、趋势或成功率。
- 不自动提交、推送或创建 PR，除非用户另行授权。

## 3. 智能体执行协议

每个执行智能体必须遵守以下顺序：

1. 先读取本计划、产品方案、最新接口文档和 `AGENTS.md`。
2. 执行 `git status --short`，记录并保护已有修改和未跟踪文件。
3. 只修改当前任务列出的文件；发现跨任务依赖时先记录，不顺手扩大范围。
4. 页面不得直接调用 Axios，统一使用 `src/api/request.ts` 和 `src/api/modules/*`。
5. 配置统一使用 `useAppStore` 和 `src/utils/storage.ts`，不得散落调用 `localStorage`。
6. 新增业务数字前，必须能够指出对应接口、字段和统计范围。
7. 接口缺失、无权限或返回空数据时，使用错误态或空态；不得恢复 Mock。
8. 长耗时写操作不得自动重试，避免重复写入。
9. 每完成一个任务，先运行该任务的最小验证，再运行 `pnpm check`。
10. 交付时列出修改文件、验证结果、未解决问题和下一任务，不用模糊的“已优化”。

### 3.1 文件安全规则

- 禁止使用 `git reset --hard`、`git checkout --` 或批量删除未知文件。
- `docs/` 和 `tests/test-data-set/` 中已有新增材料属于用户资产，不得清理。
- 删除文件前先用 `rg` 确认没有有效引用。
- 共享文件变更保持窄范围，尤其是 `src/api/types.ts`、`src/router/*`、`src/layouts/*`。

### 3.2 测试规则

- 快速验证：`pnpm lint`、`pnpm test` 或 `pnpm build`，按任务选择。
- 完整验证：`pnpm check`。
- 当前项目没有 Playwright 测试依赖，不得为了本轮计划擅自引入完整 E2E 框架。
- 浏览器冒烟测试使用本地 Vite 服务和隔离测试用户，写入完成后清理测试记忆。

## 4. 任务依赖图

```text
T0 基线冻结
 └─ T1 接口类型与模块
     ├─ T2 导航与说明页收敛
     ├─ T3 设置、场景、智能体接入
     ├─ T4 首页真实数据
     ├─ T5 写入与数据校验
```
