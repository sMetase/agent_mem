# 智能体记忆系统前端设计文档



## 1. 项目定位

本前端是“面向大模型智能体的记忆系统”的管理与演示控制台，重点不是实时 AI 聊天，而是围绕历史对话、会话摘要、任务过程和业务元数据完成记忆写入、生成、去重融合、检索、上下文返回和接口监控。

系统面向的主要使用者包括：

- 演示人员：通过页面展示记忆系统的完整工作流程。
- 前端与后端联调人员：通过页面验证接口可用性和数据返回结果。
- 业务测试人员：通过导入测试数据、检索问题和管理记忆来验证系统效果。

## 2. 技术栈

前端采用如下技术：

- React：页面与组件开发。
- Vite：本地开发服务器和生产构建。
- TypeScript：接口类型、页面状态和业务数据约束。
- Ant Design：表单、表格、卡片、提示、按钮、标签等 UI 组件。
- Axios：统一请求后端接口。
- Zustand：保存应用配置、用户身份、记忆和任务等局部状态。
- React Router：组织页面路由和左侧菜单。
- oxlint、Vitest：代码检查和基础测试。

## 3. 整体架构

前端采用“页面层 + 业务组件层 + 接口层 + 状态与工具层”的结构。

```text
src/
  api/                  后端接口封装、请求客户端、统一响应处理、接口类型
  components/
    common/             页面容器、加载、空状态、错误兜底、确认弹窗等通用组件
    business/           记忆卡片、筛选栏、任务进度、配置表单等业务组件
  constants/            路由、菜单、记忆生成预设等常量
  hooks/                与接口调用和页面状态相关的复用逻辑
  layouts/              控制台整体布局和左侧导航
  pages/                各功能页面
  router/               路由配置、懒加载页面、异常路由兜底
  store/                Zustand 状态管理
  styles/               全局样式
  utils/                配置、存储、导入解析、格式化和提示工具
```

核心设计思路：

- 页面按老师模板中的 7 个一级模块组织，左侧菜单承载主要功能入口。
- 后端接口集中放在 `src/api/modules`，页面不直接拼接复杂请求。
- 页面通用状态统一用加载、空状态、错误提示和确认弹窗表现，避免每个页面重复写。
- 系统设置页支持配置后端 Base URL、User ID、Scene ID、Agent ID、API Key，方便联调环境切换。

## 4. 功能模块设计

### 4.1 系统总览

入口：`/`

系统总览展示当前记忆系统的关键指标和流程状态，包括接入智能体、业务场景、记忆总量、今日检索调用、上下文返回成功率等。页面用于演示系统整体能力，部分统计依赖后端管理接口。

主要能力：

- 展示系统核心指标。
- 展示记忆处理流程。
- 展示记忆类型、趋势、检索方式和最近任务。
- 当部分后端统计接口不可用时，页面显示“接口不可用”或兜底状态。

### 4.2 智能体接入与记忆数据写入

相关入口：

- `/access/agents`：智能体注册接入。
- `/access/scenes`：场景标识配置。
- `/access/credentials`：接口密钥配置。
- `/ingestion`：记忆数据导入。
- `/ingestion/validation`：数据校验与标准化。

设计目标是把外部智能体、业务场景和历史数据接入记忆系统。

当前重点能力：

- 支持对话记录、历史会话、任务过程三种导入模式。
- 支持 JSON/CSV 文件导入。
- 支持手动填写单条记忆导入。
- 导入时根据模式组装对应的写入请求。
- 数据校验页用于展示字段检查和标准化思路。

导入模式说明：

| 模式 | 用途 | 主要字段 |
| --- | --- | --- |
| dialogue | 导入用户与智能体的历史对话 | content、role、scene_id、task_id |
| session | 导入已经结束的历史会话摘要 | session_summary、session_time、session_source |
| task_process | 导入任务过程和执行结果 | task_goal、task_progress、task_result |

### 4.3 通用记忆建模与多层记忆管理

相关入口：

- `/memory/user`：用户级记忆。
- `/memory/session`：会话级记忆。
- `/memory/task`：任务级记忆。
- `/memory`：智能体级或综合记忆管理。

该模块用于查看、筛选、编辑和删除已经写入系统的记忆。

当前能力：

- 按用户、场景、任务等条件查询记忆。
- 展示记忆内容、摘要、类型、状态、标签、重要性和置信度等信息。
- 支持编辑记忆内容和元数据。
- 支持“清除记忆”模式：进入选择状态后勾选部分记忆，或全选后批量清除。
- 支持后端删除接口异常时，通过状态更新方式进行软删除兜底。

### 4.4 记忆生成与去重融合

入口：`/generation`

该模块对应记忆从原始文本到结构化记忆的处理过程，包括偏好提取、关键事实、任务状态、历史决策、冲突识别、相似记忆去重、融合管理和低价值内容过滤。

当前能力：

- 单条文本生成记忆。
- 批量文本生成记忆。
- 支持异步生成任务提交和状态恢复。
- 展示生成结果、事件类型、统计结果和处理明细。
- 按不同子功能入口切换说明和默认参数。

### 4.5 多信号融合记忆检索

相关入口：

- `/retrieval/semantic`：语义向量检索。
- `/retrieval/keyword`：关键词检索。
- `/retrieval/metadata`：元数据过滤。
- `/retrieval/fusion`：融合排序。
- `/retrieval/top-k`：Top-K 返回。

该模块用于从已写入记忆中检索与当前问题或任务最相关的结果。

当前能力：

- 输入自然语言查询。
- 设置记忆类型、状态、时间、Top-K 数量等条件。
- 调用后端检索接口返回相关记忆结果。
- 展示总候选数、耗时、结果列表和相关元数据。

### 4.6 记忆上下文返回

相关入口：

- `/context/json`：结构化 JSON 返回。
- `/context/text`：文本上下文片段返回。
- `/context/relevance`：相关性筛选。
- `/context/length`：长度控制与压缩。

该模块用于把检索到的记忆组织成可供智能体后续任务使用的上下文。

当前能力：

- 设置用户、场景、任务、查询内容和长度限制。
- 调用上下文接口获取结构化结果。
- 展示 JSON 结果和文本片段。
- 支持围绕相关性、长度控制等子功能进行演示。

### 4.7 任务过程管理

入口：`/task`

该模块用于管理与记忆相关的任务过程。

当前能力：

- 创建任务。
- 查询任务进度。
- 更新任务状态、进度、已完成项和待办项。
- 将任务过程与记忆数据联动。

### 4.8 接口与监控

相关入口：

- `/monitoring/health`：接口健康检查。
- `/monitoring/calls`：调用状态监控。
- `/monitoring/records`：联调记录。

该模块用于联调和演示接口状态。

当前能力：

- 检查 `/health` 是否可访问。
- 展示后端返回的应用名称、版本、状态和耗时。
- 拉取管理接口日志和检索日志。
- 展示接口状态、响应码、耗时和异常信息。

### 4.9 系统设置

相关入口：

- `/settings/connection`：基础连接设置。
- `/settings/identity`：本地用户身份。

当前能力：

- 配置后端服务 Base URL。
- 配置 User ID、Scene ID、Agent ID、API Key。
- 配置保存到浏览器本地，用于后续接口请求。
- 若填写 API Key，请求时自动携带 `X-API-Key`。

## 5. 接口设计与前端适配

前端统一通过 `src/api/client.ts` 创建 Axios 实例，并在请求前读取浏览器本地设置：

- `baseURL` 优先使用系统设置页保存的 Base URL。
- 若未保存 Base URL，则使用 `.env.development` 或 `.env.production` 中的 `VITE_API_BASE_URL`。
- 若保存了 API Key，则请求头自动携带 `X-API-Key`。
- 请求统一使用 JSON 格式。

主要接口如下：

| 功能 | 方法 | 路径 |
| --- | --- | --- |
| 健康检查 | GET | `/health` |
| 智能体注册 | POST | `/api/v1/agent/register` |
| 智能体密钥轮换 | POST | `/api/v1/agent/{agent_id}/rotate-key` |
| 场景创建 | POST | `/api/v1/scene` |
| 任务创建 | POST | `/api/v1/task` |
| 任务更新 | PUT | `/api/v1/task/{task_id}` |
| 任务进度查询 | GET | `/api/v1/task/{task_id}/progress` |
| 记忆写入 | POST | `/api/v1/memory/write` |
| 记忆检索 | POST | `/api/v1/memory/search` |
| 记忆列表 | POST | `/api/v1/memory/list` |
| 记忆统计 | GET | `/api/v1/memory/stats` |
| 记忆更新 | PUT | `/api/v1/memory/update` |
| 单条记忆删除 | DELETE | `/api/v1/memory/delete` |
| 全部记忆清除 | POST | `/api/v1/memory/delete-all` |
| 记忆上下文返回 | POST | `/api/v1/memory/context` |
| 单条记忆生成 | POST | `/api/v1/memory/generate` |
| 批量记忆生成 | POST | `/api/v1/memory/generate/batch` |
| 异步记忆生成 | POST | `/api/v1/memory/generate/async` |
| 异步生成状态查询 | GET | `/api/v1/memory/generate/{request_id}/status` |
| 管理统计 | GET | `/api/v1/admin/stats` |
| 仪表盘统计 | GET | `/api/v1/admin/dashboard` |
| 接口调用日志 | GET | `/api/v1/admin/api-logs` |
| 检索日志 | GET | `/api/v1/admin/retrieval-logs` |

## 6. 状态与异常处理

前端对异常场景做了以下兜底：

- 页面加载中显示统一 loading 状态。
- 无数据时显示统一 empty 状态。
- 接口失败时通过页面提示和局部状态展示错误原因。
- 页面级异常通过错误边界兜底，避免整个应用白屏。
- 删除记忆接口若出现服务端异常，前端会尝试通过更新记忆状态为 `deleted` 的方式完成软删除。
- 部分统计接口不可用时，总览和监控页保留页面结构并显示不可用状态。
