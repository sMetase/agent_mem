# 记忆生成与去重融合改造交接文档

## 1. 交付结论

“第三部分：记忆生成与去重融合”已由静态能力描述页改造为可直接调用后端真实接口的共享工作台。九个菜单入口现在通过不同场景预设进入同一工作台，支持单条同步、批量同步和单条异步生成，并真实展示后端返回的新增、融合、更新、丢弃、冲突及逐条处理明细。

本次采用“保留并重构原有生成工作台、删除静态能力描述页”的方案，原因如下：

- 原生成页已经具备同步和批量接口调用基础，继续演进的实施风险低于重新创建九套页面。
- 九个能力共用相同请求和响应结构，以查询参数驱动预设可避免重复逻辑和后续行为漂移。
- 原 `/capabilities/:capabilityId` 链接保留兼容重定向，已有收藏或文档链接不会直接失效。
- 删除不再使用的能力描述组件和定义，避免真实工作台与静态说明长期并存造成误导。

## 2. 页面与路由

九个真实入口如下：

| 能力入口 | 新路径 | 默认聚焦 |
| --- | --- | --- |
| 用户偏好提取 | `/generation?view=preference` | `preference` 类型 |
| 关键事实提取 | `/generation?view=fact` | `key_fact` / `fact` / `constraint` 类型 |
| 任务状态生成 | `/generation?view=task-state` | `task_state` / `task` 类型 |
| 历史决策沉淀 | `/generation?view=decision` | `decision` 类型 |
| 冲突检测 | `/generation?view=conflict` | `conflict` 动作 |
| 冲突记忆去重 | `/generation?view=conflict-dedup` | 冲突、更新、丢弃动作 |
| 相似记忆去重 | `/generation?view=similar-dedup` | 融合、更新、丢弃动作 |
| 记忆融合管理 | `/generation?view=fusion` | 融合、更新动作 |
| 低价值内容过滤 | `/generation?view=low-value` | 丢弃动作 |

`/generation` 仍可访问完整能力工作台。原静态能力链接会重定向到对应预设；原“智能体级记忆”链接会进入 `/memory`。

## 3. 功能说明

### 3.1 请求模式

- 单条同步：调用 `POST /api/v1/memory/generate`。
- 批量同步：调用 `POST /api/v1/memory/generate/batch`，每行一条文本，一次最多 50 条。
- 单条异步：调用 `POST /api/v1/memory/generate/async`，随后轮询 `GET /api/v1/memory/generate/{request_id}/status`。

异步任务会保存版本化的浏览器会话快照，内容包括请求 ID、原始文本、来源页面预设、用户、场景、任务、会话及抽取类型。页面刷新后会恢复到异步模式并明确标注“已恢复任务”，在 30 分钟有效期内继续查询；不会把旧异步结果误归属为新的同步请求。任务完成、失败或后端返回不存在时会清理快照。轮询失败不会自动重提生成请求，避免重复写入。

### 3.2 参数与结果

- 基础参数：User ID、Scene ID、Agent ID、Task ID、抽取类型。
- 高级参数：Session ID；单条模式另支持来源记录 ID 和 Metadata JSON。
- 结果汇总：生成记忆数、新增数、融合数、更新数、丢弃数、冲突数。
- 结果明细：来源输入、处理动作、记忆内容、类型、重要性、置信度、记忆 ID、后端说明。

页面仅展示后端真实返回值。场景聚焦没有命中时会明确显示空结果，并允许关闭聚焦查看本次全部明细，不会构造冲突、融合或过滤原因。

### 3.3 状态与稳定性

- 流水线卡片在执行前显示“等待执行”，同步或批量运行时显示“执行中”，只有真实结果返回后才显示“已完成”。
- 异步模式只展示后端总体进度，不伪造各阶段进度。
- 超时提示明确说明后端可能已经写入，要求先到记忆列表核对，避免立即重复提交。
- 生成流水线使用适应容器宽度的网格；结果表格保留横向滚动，兼顾桌面和窄屏。
- 全局消息提示已接入 Ant Design 应用上下文，消除静态消息 API 的控制台警告。

## 6. 后续维护建议

- 若后端新增人工冲突决策、融合预览或过滤规则配置接口，应在当前共享工作台增加独立操作区，不要用前端模拟结果。
- 若异步任务迁移到持久化队列，可将会话快照升级为服务端任务列表，并保留当前 `request_id` 状态查询兼容。
- 若后端扩展处理动作或记忆类型，应同步更新动作标签、场景聚焦映射和测试用例。
- 生产环境应通过 `VITE_API_BASE_URL` 或系统设置配置实际服务地址，不要在业务组件中写死后端地址。
