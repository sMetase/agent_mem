智能体记忆系统批量记忆检索测试流程

一、测试材料

本次测试共准备 60 条输入数据，分为 3 个场景：

1. 批量测试数据-物流场景-20条.json
   scene_id：logistics-test
   包含任务：路线优化、仓储管理、配送执行、冷链合规

2. 批量测试数据-客服场景-20条.json
   scene_id：customer-service-test
   包含任务：退款处理、物流服务、会员管理、投诉处理

3. 批量测试数据-运维场景-20条.json
   scene_id：ops-test
   包含任务：故障处置、生产发布、数据库管理、安全管理

4. 批量检索测试问题-24题.json
   该文件只用于查看测试问题和预期结果，不要上传到记忆导入页面。

5. 批量检索测试结果记录模板.txt
   用于记录每道题的实际结果、耗时和截图编号。

注意：
后端会从一条输入内容中提取一条或多条记忆，也可能对相近内容进行合并。因此导入 60 条原始记录后，最终记忆数量不一定正好是 60 条，处于几十到几百条之间都属于正常现象。


二、测试前准备

1. 启动前端并打开：

   http://localhost:5173

2. 进入“系统设置”。
3. Base URL 设置为后端地址：

   http://120.27.207.238:8000

4. User ID 设置为一个专门用于本次测试的新用户：

   retrieval_test_user_001

5. 保存配置。
6. 进入“接口健康检查”，点击“开始巡检”。
7. 确认后端健康检查和安全接口检查正常后，再开始导入。

为什么使用新的 User ID：
这样可以避免之前课堂演示数据影响检索结果，也方便测试结束后统一清理。


三、分场景导入 60 条数据

三个文件必须分开导入，不要同时选择。

第一批：物流场景

1. 打开：
   智能体接入与记忆数据写入 → 对话记录写入
2. 确认选择的是“对话记录”。
3. 上传：
   批量测试数据-物流场景-20条.json
4. 页面显示“已解析 20 条记录”后，点击“校验并写入”。
5. 等待写入完成，记录成功处理数量和生成记忆数量。
6. 建议截图保存本批次的成功提示。

第二批：客服场景

1. 继续停留在“对话记录写入”页面。
2. 上传：
   批量测试数据-客服场景-20条.json
3. 确认解析 20 条后点击“校验并写入”。
4. 等待写入完成并截图。

第三批：运维场景

1. 上传：
   批量测试数据-运维场景-20条.json
2. 确认解析 20 条后点击“校验并写入”。
3. 等待写入完成并截图。

注意：

1. 每批写入需要逐条调用后端，可能等待数分钟，请不要连续点击按钮。
2. 如果中途提示“已处理 X 条，后续数据处理失败”，先记录已经成功的数量和错误信息，不要立即重复导入整批，否则可能产生重复记忆。
3. 三批全部成功后等待约 10 秒，让后端完成记忆抽取和索引。


四、检查记忆是否已经保存

1. 打开：
   通用记忆建模与多层记忆管理 → 用户级记忆
2. 点击右上角“刷新”。
3. 确认列表中出现物流、客服和运维相关内容。
4. 分别搜索以下关键词进行快速检查：

   冷链
   退款
   P1 故障

5. 如果三类关键词都能找到相关内容，说明三个场景均已写入。
6. 记录页面显示的记忆数量并截图。


五、执行 24 道检索问题

1. 使用文本编辑器打开：
   批量检索测试问题-24题.json
2. 打开前端页面：
   多信号融合记忆检索 → 语义向量检索
3. 从 Q01 开始，将 query 字段中的问题复制到检索框。
4. Top-K 设置为 5。
5. 如果页面支持 Scene ID 和 Task ID 筛选：
   - 第一轮不设置筛选，检查全库语义检索能力。
   - 第二轮填写题目中的 expected_scene_id 和 expected_task_id，检查场景及任务过滤能力。
6. 点击检索。
7. 查看前 5 条结果，重点记录：
   - 是否出现 expected_keywords 中的关键词或同义内容。
   - 是否来自预期 scene_id。
   - 是否来自预期 task_id。
   - 预期内容排在第几名。
   - 返回结果数量。
   - 页面显示的检索耗时。
8. 将结果填写到：
   批量检索测试结果记录模板.txt
9. 按相同方式完成 Q01 至 Q24。


六、通过标准

短问题、简单问题：

1. 前 3 条结果中至少有 1 条包含预期核心事实。
2. 结果应优先来自预期场景和任务。

长问题、复杂问题：

1. 前 5 条结果中至少有 2 条相关记忆。
2. 多个 expected_keywords 能在不同结果中被覆盖。
3. 不要求返回文本与原始数据逐字一致，只要事实含义一致即可。

场景过滤：

1. 指定 logistics-test 时，不应优先返回客服或运维内容。
2. 指定 customer-service-test 时，不应优先返回物流或运维内容。
3. 指定 ops-test 时，不应优先返回物流或客服内容。

任务过滤：

1. 指定 task_id 后，结果应集中在对应任务。
2. 如果仍返回其他任务内容，应记录为“任务过滤疑似无效”。


七、结果等级建议

通过：
前 3 条中出现正确核心事实，场景和任务正确。

基本通过：
前 5 条中出现正确事实，但排序较后，或只覆盖部分关键词。

失败：
前 5 条均无相关事实，返回错误场景，接口报错或没有结果。


八、建议截图

至少保留以下截图：

1. 三个 JSON 文件分别解析为 20 条记录。
2. 三个批次各自写入成功的提示。
3. 用户级记忆页面显示批量数据。
4. 一个短问题的成功检索结果。
5. 一个长问题的多结果召回。
6. 一个指定场景后的检索结果。
7. 一个指定任务后的检索结果。
8. 如果出现失败，保存问题、返回结果和错误提示。


九、测试结束后的清理

1. 进入“用户级记忆”页面。
2. 确认当前 User ID 是 retrieval_test_user_001。
3. 点击“清除记忆”。
4. 选择本次测试数据并执行清除。
5. 不要清除其他用户的记忆。
